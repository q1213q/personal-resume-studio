# 个人简历网站工作室使用说明书

Personal Resume Studio · 首个开源版本 v1.0.0

这套 Skill 帮你和 AI 一起，把真实履历做成个人简历网站，并完成从本地预览到公网发布的交付。你决定网站表达什么、采用哪套模板；AI 按工作流程整理资料、制作和验收。

它不是只换姓名的一张固定网页，也不是输入一个网址就能自动复制所有内容的抓取器。内置底稿只是一个可选模板，其他模板可以有完全不同的版式、配色和技术结构。

## 1. 先准备四样东西

| 材料 | 怎么准备 |
| --- | --- |
| 真实履历 | Word、PDF 或文字均可，包含职业定位、工作经历、职责、项目和教育信息 |
| 照片与作品 | 使用你有权使用的原文件；说明是否允许调色、裁切或压缩；没有照片也能制作 |
| 模板或参考 | 可以是模板文件、源码包、网页链接、截图，或者你想浏览的模板网站 |
| 使用与发布需求 | 给谁看、中文还是其他语言、求职或演示、是否上线、是否已有托管平台 |

不需要一次整理得非常完美。先交已有资料，AI 应列出缺项并推进其余工作。数据要说明时间、单位和归属，例如“参与项目的整体规模”不能改成“本人独立完成的业绩”。联系方式只放你愿意公开的部分。

## 2. 下载、安装和启用

### 在支持 Skill 的 AI 工具里

从仓库的 **Code → Download ZIP** 或 **Releases** 下载完整文件包。解压后，如果文件夹名称带分支或版本后缀，把用于安装的文件夹命名为 `personal-resume-studio`。不要只保留 `SKILL.md`，它需要同目录下的资料和脚本。

让工具按其当前技能安装规则安装这个文件夹。你可以直接说：

> 请将这个 personal-resume-studio 文件夹安装为 Skill，先读取其中的 SKILL.md，不要把我的个人履历放进技能安装目录。

在以 `~/.codex/skills` 为技能目录的 Codex 环境，目录结构应是：

```text
~/.codex/skills/personal-resume-studio/
  SKILL.md
  README.md
  LICENSE
  agents/
  assets/
  docs/
  references/
  scripts/
```

设置了自定义 `CODEX_HOME` 时使用其 `skills` 子目录。其他工具以自己的技能目录和安装方式为准。安装后如未发现技能，重新打开任务或刷新技能列表，检查是否多套了一层文件夹。

### 在不能安装 Skill 的 AI 里

如果 AI 能阅读附件，上传完整文件夹或 ZIP，并说：

> 先读取包内 SKILL.md，再根据我的资料执行相关流程。需要参考文件时继续读取，不要只看 README 就开始生成。

是否能实际生成文件、浏览网页、编辑图片、上传网站，取决于这个 AI 的工具能力。没有这些能力的 AI 可以帮助整理资料与解释步骤，文件操作和发布需要你手工完成；不能假装已经完成上传。

### 完全手工使用

阅读本说明书，选模板，按模板的方式编辑内容，再做本地验收和上传。若选择包内底稿，可直接复制网页文件使用，第 5 节给出了操作方法。

## 3. 选择你想要的制作方式

### 方式 A：我已经有喜欢的模板

把具体模板、演示网址或截图交给 AI：

> 使用 $personal-resume-studio。我已经选好这个模板，请按它的版式、字体层级、配色、图文比例和动态表现制作，换成我的真实履历与照片。完成整站、手机适配和完整简历入口，不能还原的部分请说明，不要擅自换一套设计。

有源码时优先沿用原模板结构。只有网页时，AI 应实际观察后独立实现；只有截图时，只能确认可见部分，未展示的交互需要补充依据。网页可以预览不等于其源码、照片和字体可以自由复制，使用外部模板时遵守其授权条件。

### 方式 B：我还没想好，先看模板

把你喜欢的设计平台、模板网站或候选链接交给 AI：

> 使用 $personal-resume-studio。先从这些参考网站里挑几套适合我的简历模板，给我实际预览链接、适合之处和主要区别。等我选定后再制作，不要默认使用内置底稿。

你也可以自己浏览后，把选中的具体网页交给 AI。希望 AI 直接决定时，明确说“由你选一套并直接制作”；已选好之后不必继续反复选稿。

### 我只想改或发布已有网站

> 使用 $personal-resume-studio。沿用我的正式版本，只处理我指定的问题，同步受影响的阅读页和下载文件。需要上线时更新对应部署，不另做一套网站。

## 4. 从制作到交付，会经过什么

1. **整理资料。** 确定公开内容，记录最新更正，区分真实事实、缺项和不公开信息。
2. **确认模板。** 确定还原目标；未要求比较时不额外制作大量方案。
3. **完成整站。** 把真实履历放入合适栏目，处理照片、文字和其他页面的一致性。
4. **调整动态。** 动效应有触发、播放和结束状态。演示开场可以更明显，正文阅读阶段应稳定。
5. **完成手机和简历入口。** 检查菜单、长文字、窄屏、阅读页、打印和实际附件下载。
6. **本地验收。** 核对事实与照片清晰度，把用户选定方案应用到正式入口。
7. **打包发布。** 只上传公开文件，完成必要的账号操作，取得真正公开的网址。
8. **公网实测和交接。** 重测线上显示和功能，说明源文件在哪里、以后怎么更新和回退。

这不是每个节点都要重新确认的流程。已有信息就继续使用；必要的账号登录、模板选择或公开范围缺失时才需要你补充。

### 怎样给 AI 反馈更有效

可以直接说“只改首页排版”“照片保持原图，不压缩”“开场结束后装饰淡出并停止”“这里的岗位改成我刚给你的表述”“我需要实际 PDF 下载，不只是阅读页”。指出范围和期望结果，有助于避免改动越来越大。

## 5. 选择内置底稿：不用写代码也能开始

内置底稿没有第三方运行依赖，主页和完整阅读页共享一份 `profile.js`。你可以让 AI 编辑，也可以自己用文本编辑器填写。

1. 把 `assets/starter/` **复制到仓库外**，作为自己的项目目录；不要直接在 Skill 中填写真实信息。
2. 修改复制出来的 `profile.js`，将占位文字换成真实资料，保留引号、逗号、方括号。
3. 照片放在项目的 `assets/` 下，将 `photo` 填为相对路径，如 `assets/portrait.png`。
4. `layout` 可选 `overlay` 图文叠印、`split` 左文右图、`type` 文字优先。这里只控制内置底稿，不限制其他模板。
5. 有 PDF／Word 时放进 `assets/`，填写 `resume.file` 和 `resume.filename`。没有文件时入口为“查看完整履历”，可以在阅读页打印或另存 PDF。
6. 双击 `index.html` 预览。正式验收再通过本地 HTTP 服务打开，避免本地文件与托管环境差异。
7. 核对真实资料后把 `draft` 改成 `false`，保留项目里的 `LICENSE`。

字段对应说明见 [内容结构](../references/content-model.md)。空数组可以保留，不要为了填满网页编造工作经历。修改 `profile.js` 不会自动改写另外提供的 PDF／Word 文件，需要同步修改附件。

### 用脚本生成

需要 Python 3.9 或更高版本。脚本只用标准库，不需要安装额外 Python 包。复制 `assets/profile.example.json` 到自己的私人目录，填写后在 Skill 根目录执行。下面路径均需替换，有空格时加引号：

```bash
python3 scripts/new_resume.py --data /path/to/profile.json --out /path/to/my-resume
```

需要附带照片和简历时，可以使用：

```bash
python3 scripts/new_resume.py --data /path/to/profile.json --out /path/to/my-resume --photo /path/to/photo.png --resume /path/to/resume.pdf
python3 scripts/check_resume.py /path/to/my-resume --final
```

两条生成命令是可选用法，不是必须顺次运行。生成器拒绝覆盖非空目录；已有项目直接编辑资料或选新输出目录。Windows 按本机 Python 的安装方式将 `python3` 换为 `python` 或 `py`。

照片与附件按原字节复制，不会在生成时降低画质。`--final` 会拒绝未填写示例与草稿标记，但不检查业绩是否真实、排版是否美观。

## 6. 从本地页面到公开网站

### 先区分三种文件包

| 文件包 | 装的是什么 | 交给谁 |
| --- | --- | --- |
| Skill 开源包 | 通用说明、模板、工具、许可证 | 其他 AI 和想制作自己简历的人 |
| 私人项目目录 | 自己的资料、源文件、原照片、协作记录 | 自己和授权协作者 |
| 网站发布包 | 经过确认可公开的网页、图片、脚本、附件 | 网站托管平台 |

**发布网站时不要把整个 Skill 或私人项目目录上传。** 分享 Skill 时也不要塞入已经填好的真实资料。

### 静态托管还是内网穿透

带动画的网页也可以是静态网页。只含前端页面和下载文件的简历站通常适合静态云托管，不必先买云服务器。上传的文件由云端提供时，通常不依赖你的电脑开机。

内网穿透则把本地服务通过公网入口提供给别人访问；本机作为源站时，需要电脑、服务和网络在线。两种方式不能混为一谈。需要数据库、登录或后端 API 时，应另行明确后端方案。

已有托管平台就告诉 AI 名称和目标项目；没有时说明读者地区、长期展示还是临时演示、预算及独立域名需求。账号登录和验证码自己操作，不要把密码粘进公开文件。

### 生成公开文件包

复制 `assets/publish-files.example.json` 到私人项目旁，按成品列出每一个要公开的文件。默认示例适用于没有附加素材的内置底稿；你新增的照片、遮罩、字体、完整简历等都要加入清单。外部模板需要重新填写清单，并先完成其构建。

```bash
python3 scripts/pack_site.py --source /path/to/my-resume --files /path/to/publish-files.json --out /path/to/release-v1
```

输出的 `site/` 和 `site.zip` 用于上传，`manifest.json` 留在私人项目中用于校验。ZIP 根目录直接放网页入口。打包是无损归档，不会压缩照片画质；工具只复制清单里的文件，不判断文件内容是否包含隐私，也不自动发现漏掉的资源。

### 上传与验证

让 AI 按所选平台的官方流程上传，或自己在支持直接上传的控制台选择 `site.zip`／`site/` 内容。如果出现认领步骤，要确认资源归属；控制台链接或认领页不是最终网站地址。

拿到真实公开地址后，运行可选文件校验。下面域名只是示例：

```bash
python3 scripts/verify_site.py --base-url https://example.com/ --manifest /path/to/release-v1/manifest.json --report /path/to/qa/online-v1.json
```

工具优先使用本机 curl，没有时使用 Python 的 HTTPS 客户端。它检查每个文件是否请求成功、大小和哈希是否匹配，能识别“下载按钮实际返回一个错误网页”的情况。它不会替你点击菜单，也不证明所有地区访问都快。

发布操作与平台示例详见 [发布流程](../references/deployment.md)。平台的额度、时效、命令和更新方式可能变化，以当前官方信息为准。

## 7. 验收时亲自看这几件事

- 正式入口是你选中的版本，显示的名字、经历、数字、时间和联系方式正确。
- 照片清晰，符合你允许的处理范围；菜单、标题和正文在手机上不被挡住。
- 首次进入、从其他栏目返回、重播和减少动态设置下都能正常阅读。
- 项目链接和完整阅读页能打开，下载得到的文件内容是最新版。
- 打开的是公开地址，别人无需登录你的账号也能看见公开内容。
- 已有源文件和可回退版本，知道后续要更新哪个托管项目或网址。

AI 只测试了手机尺寸模拟时，应明确告诉你。最好再用自己的手机浏览器或微信内置浏览器打开一次；在一种网络下正常也不代表其他网络已经测试过。

## 8. 后续修改和换 AI 接手

将 [项目记录模板](../assets/project-brief.md) 复制到私人项目旁，填入模板选择、事实更正、正式文件、部署版本和下一步。不要把填好的记录提交到开源仓库。

修改时从可维护源文件开始，再同步阅读页和 PDF／Word，重新打包和发布。不要只改临时上传目录。部分平台每次发布都会生成新网址，需要分享新地址；支持原址更新的平台也要确认生产版本已经切换。

换 AI 时，把私人项目和项目记录交给它，并说：

> 请使用 personal-resume-studio，先读取我的项目记录，确认正式版本、已经选择的模板和不再采用的方案，再完成下面的修改。不要重新开始选模板。

## 9. 常见问题

**别人做出来会和我的网站一模一样吗？** 只有选择相同模板并要求还原时，风格才会相近。Skill 默认保留模板选择，不强迫使用内置版式。

**只发一句话就能全自动上线吗？** 文件与工具齐全、账号已可用时，AI 可以连续完成很多步骤。事实缺失、没有选择模板、需要验证码或平台付款时，仍需要你提供必要信息或操作。

**照片会被自动压缩吗？** 生成和打包脚本不会改变图片字节。需要修图或优化时，应保留原文件并遵守你允许的范围；拒绝压缩时不能偷偷换成低清照片。

**网页动画怎么在手机上不一样？** 检查浏览器支持、减少动态偏好、图层与字体。有些箭头或星号字符会变成彩色 emoji，需要一致外观时使用 SVG 或 CSS 图形。详见 [动效与验收](../references/motion-and-qa.md)。

**公网突然变慢怎么办？** 先核对同一网址与版本，区分代理、网络、资源传输、图片解码及故意设置的动画等待。不要先把照片压糊，也不要擅自关全局代理。详见 [性能排查](../references/performance.md)。

**发布后能立即在搜索引擎搜到吗？** 不能保证。公网访问、独立域名和搜索收录是不同状态。标题、正文、站点地图和站长平台提交只是准备工作，不承诺即时收录或排名。

**用这个 Skill 做客户项目可以吗？** 可以在 [MIT 许可证](../LICENSE) 条件下使用、修改和商用本项目，保留版权与许可声明。外部模板、照片、字体及客户资料需遵守各自的使用条件；许可证没有替你取得第三方素材权限。

**遇到问题怎么反馈？** 在仓库提交 Issue，描述现象、操作步骤、系统／浏览器和预期结果。只用占位或合成资料复现，不上传真实简历、照片、凭据或未经处理的私有日志。贡献改进见 [贡献指南](../CONTRIBUTING.md)。
