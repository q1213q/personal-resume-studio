# 从本地网站到公网发布

适用于已有网站准备上线、换平台、绑定域名或更新内容。先定位真实文件，再选择发布方式，最后检查公开网址。平台价格、免费额度、时效、区域及命令可能变化；执行时查当前官方文档与工具帮助，不把本文示例当成永久产品承诺。

## 1. 识别要发布的东西

记录四个位置：**可维护源目录 → 构建产物 → 干净的上传目录 → 公网网址**。

- 原生 HTML／CSS／JS：通常无需构建，复制公开文件即可。
- 有构建工具的模板：读项目说明、依赖清单和锁文件，使用该项目的构建命令；检查实际产物，不假设输出总是 `dist`。
- 静态导出：确认每个页面有可托管的输出，不能把服务端模板、API 路由或开发服务器直接上传为静态网站。
- 需要后端：说明登录、数据库、表单接收、私密 API 等由什么服务承担。前端文件里不能放密钥；没有后端时不做会虚假提示提交成功的联系表单。

动效由浏览器执行，也可以属于静态网站。一个普通的个人简历站不因为照片入场、滚动效果或下载按钮就需要购买服务器。

## 2. 根据用途选择承载方式

| 方式 | 适合的情况 | 电脑关机后 | 必须核实 |
| --- | --- | --- | --- |
| 静态云托管／文件托管 | 持续展示个人站、作品集、下载附件 | 文件已在云端，通常不依赖本机 | 账号归属、有效期、额度、区域、是否能原址更新、自定义域名 |
| 内网穿透 | 临时远程演示本地网站或已有动态服务 | 本机是源站时将不可用 | 本地进程、电脑休眠、网络、隧道存活与访问限制 |
| 云服务器／带后端的平台 | 确有服务端程序或特殊运维需求 | 云端运行不依赖个人电脑 | 程序保活、HTTPS、安全更新、备份和成本 |

沿用用户选定的平台。没有偏好时，为轻量静态站优先寻找静态托管，按目标读者所在地区和实际测试选择，不因网站名称或中文界面推断有中国大陆节点。需要稳定传播时优先确认原址更新和自定义域名支持。

不要把域名购买作为上传的必经步骤：部分平台提供默认网址，可先预览与验收。域名让地址更容易长期使用，实际支持与绑定方式由平台决定。

## 3. 准备只含公开内容的发布包

先合并这一轮已确认修订并保存可回退版本，再打包。原图、网站、阅读页和 PDF／DOCX 应是同一套内容。

1. 从已确认成品枚举公开文件，检查 HTML、CSS、JS 中的路径及运行时引用；包括字体、遮罩、封面和完整简历。外部资源则检查权限、可达性与失败回退。
2. 复制 `assets/publish-files.example.json` 到项目旁，改成实际需要的文件列表。示例只覆盖自带底稿，不会自动包含后来添加的照片、附件或外部模板文件。使用自带底稿时保留其中的 `LICENSE`，使用其他模板时保留其要求的许可声明。
3. 把工作笔记、原始私有履历、凭据、备份、比较稿、依赖目录、测试截图与报告留在外面。公开使用的联系信息需与用户确认范围一致。
4. 删除开发专用网址依赖，检查 `localhost`、本地绝对路径、资源大小写和子目录路径。链接应面向正式部署方式；不要盲目替换所有 URL。
5. 用清单打包。下面所有路径都是需要替换的占位路径；命令在 Skill 目录运行：

```bash
python3 scripts/pack_site.py --source /path/to/site-or-dist --files /path/to/publish-files.json --out /path/to/release-v1
```

输出：

```text
release-v1/
  site/            ← 上传这个目录的内容
    index.html
    ...
  site.zip         ← ZIP 根目录直接是 index.html
  manifest.json    ← 路径、字节数、SHA-256；留在项目私有记录
```

工具按清单逐字节复制，不修改图片和简历、不扫描文件内容中的隐私、不推断资源依赖、不自动执行构建或上传。它拒绝路径越界、符号链接和常见私有文件名，但**不能代替人工检查公开内容**。若平台需要配置文件，按官方要求在控制台或专门的部署流程设置；不绕过拒绝检查把整目录塞进去。

本地先在 `site/` 下运行 HTTP 服务并打开页面，例如 `python3 -m http.server 8000 --bind 127.0.0.1`。检查独立访问阅读页和实际附件，不能只检查首页。手机实测本地站需要同一可信网络中的可访问地址或公开预览地址；手机里的 `127.0.0.1` 指手机自身。

## 4. 在所选平台执行发布

已获得发布授权时直接完成。还没确定公开内容时先交付发布包，再针对待公开范围澄清。账号登录、验证码或套餐支付交给用户必要操作，其余继续完成；不把密码、Cookie、令牌或认证缓存放入 Skill、网页、打包目录和日志。

### 上传型静态平台：以 EdgeOne Makers 为例

在控制台选择直接上传，上传构建完成的文件夹或 ZIP。根目录应有 `index.html`；上传的是 `site/` 内容或 `site.zip`，不是包含私有清单的整个 `release-v1/`。直接上传不会替你安装依赖或构建源码。首次创建后，后续在同一项目下创建部署，明确预览环境和生产环境，等正式部署状态成功后再访问正式地址。具体入口与限制按 [官方直接上传文档](https://pages.edgeone.ai/document/direct-upload) 核实。

没有自动化接口也能按控制台完成。不要为了使用某个工具强迫用户换托管商。

### 花生壳：先区分文件托管与隧道

花生壳 CLI 提供文件托管与内网穿透等能力，不能统称为“网站放到本机后永远在线”。先查 [官方 CLI 介绍](https://hsk.oray.com/cases/cli?ici=HSK_CLI) 和 [安装／使用说明](https://hsk.oray.com/doc/cli-setup.md)。本机已有 `hsk-cli` 技能时可以读取其说明；没有该技能仍可按官方文档或控制台操作，不将它设为此包的硬依赖。

执行前查看已安装 CLI 版本、`file-hosting --help` 和登录状态。当前工具帮助支持时，可用以下形式上传公开目录：

```bash
hsk-cli file-hosting /path/to/release-v1/site --entry-file index.html --format json
```

解析真实结果并区分上传成功、待认领、认领完成、公网可访问。账号显示已登录不证明某个资源已认领；应检查该资源结果或控制台中的归属。无需打印令牌来确认登录。

**更新链接尤其要核实。** 有些版本的文件托管不支持覆盖既有资源，每次上传生成新地址；不要套用已下线参数或擅自保证沿用旧网址。先集中完成修订再发布，并把新旧地址记在项目记录中。资源认领成功也不等于永久免费、永不失效，期限与额度以当前平台条件为准。

只有用户需要访问本地运行服务时才配置隧道。静态上传失败时先解释具体原因，不静默改成需要电脑一直开着的方案。不为静态文件上传自动安装系统守护进程或更改全局网络设置。

## 5. 公网实测：上传成功还不是验收完成

用实际正式网址打开，而非本地、后台或认领页。测试首页、刷新、旧锚点、重播、菜单、项目入口、完整阅读和下载。没有用户登录状态的浏览器也应能读到公开内容。

可先比对全部公开文件：

```bash
python3 scripts/verify_site.py --base-url https://example.com/ --manifest /path/to/release-v1/manifest.json --report /path/to/qa/online.json
```

工具需要 Python 3；优先使用已安装的 curl，否则使用 Python 标准库 HTTPS 客户端。它保留证书校验、设置超时，逐个记录状态、最终地址、耗时、字节数与哈希。遇到文件缺失、返回错误 HTML 或字节不一致会失败，即使 HTTP 状态是 200 也不能混过去。

托管商若合法改写 HTML／注入统计代码，哈希变化需单独查看差异和平台说明；不要直接忽略失败，也不要说文件“完全一致”。文件校验无法证明交互正常或所有网络都快。浏览器和手机验证按 [动效与验收](motion-and-qa.md) 执行，慢加载按 [性能排查](performance.md) 执行。

常见部署问题：

| 问题 | 定位方法 |
| --- | --- |
| 首页 404／空白 | 入口层级、发布目录、是否误传源码、脚本报错、资源路径 |
| 阅读页打不开 | 平台是否支持目录索引／路由重写；必要时链接明确写 `resume/index.html`，并验证文件存在 |
| 下载得到网页或空文件 | 对比实际文件类型、大小和哈希；查看重定向、权限、跨域与 Content-Disposition |
| 手机版箭头变彩色图标 | Unicode 被系统当成 emoji；使用 SVG 或 CSS 图形并重新实测 |
| 线上仍是旧内容 | 当前公开地址、部署状态、资源版本、CDN／浏览器缓存和 Service Worker；先核对版本再清缓存 |
| CSS 和照片丢失 | URL 大小写、路径编码、根目录与子路径、遮罩和字体是否入包 |

下载提示只应说明“已发起下载”或提供查看入口。至少检验下载响应的真实字节，有浏览器下载能力时再打开保存的 PDF／DOCX 看内容；不宣称文件一定落在用户的某个文件夹。

## 6. 域名、HTTPS 与可搜索

用户需要独立域名时，先核实当前平台是否支持以及套餐条件。按控制台给出的记录类型、主机记录和值配置 DNS，避免覆盖同域名既有网站或邮件记录。等 DNS 验证、证书状态和 HTTPS 访问正常，检查主域名、跳转及下载地址后再交付。

国内目标读者不等于一律同一种备案路径。实际采用中国大陆节点时，按平台当前要求核实主体、域名和备案资格；海外或不含大陆的区域也要遵循其服务条件。不根据域名后缀、公司所在地或“免费”推断可免备案。参考 [EdgeOne 自定义域名及区域说明](https://pages.edgeone.ai/document/custom-domain)，其他平台查各自官方规则。

基础搜索准备包括真实的页面标题与描述、合理标题结构、图片替代文本、可访问的履历文字；若模板完全靠 JavaScript 填入正文，可考虑构建时输出静态正文。正式地址稳定后再配置 canonical、robots.txt 和 sitemap，避免指向临时预览站。需要推广时按目标搜索引擎的站长平台流程验证与提交；公开上线不等于已收录，更不保证排名。分享卡片、联系方式及索引范围也要符合用户意愿。

## 7. 维护、回退与交接

每次更新都从可维护源文件开始，重新生成并核对发布包；不能只改临时上传目录，让下一次构建覆盖修订。保留上一版源文件／产物、校验清单和部署标识。支持原址部署的平台使用同一项目发布，并核实当前生产别名；生成新链接的平台明确通知地址变化。

回退前定位用户所指的稳定版本，恢复页面、图片和下载文件的一整套产物；有平台回滚就使用其历史部署，否则重新上传保留的稳定产物。回退后也测试正式地址。未经要求不删除旧资源、停服务、购买套餐或改无关 DNS。

最终交付写清：正式链接、源文件与发布包、托管方式及本机是否必须在线、归属／有效期中已核实的部分、原图策略、实际测试范围与已知限制、更新和回退方式。只差用户登录时指出具体平台和操作，并交付已准备好的包；不把待登录写成“已上线”。
